# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Autonomous trading bot for **Polymarket** (Polygon prediction markets). Continuous loop: pull active markets from the Gamma API → filter (volume, probability window, per-event clustering) → gather news → ask a Groq LLM whether to trade → risk-check → place limit BUY orders on the Polymarket CLOB. Optionally exits positions on take-profit/stop-loss and reports portfolio P/L to Discord. **No dry-run mode** — `python main.py` with a funded wallet trades real money.

`README.md` (Romanian) is the operator guide; this file is the engineering map. Source comments and most log messages are in **Romanian** — match that style when editing.

## Configuration

Env-driven via `config/settings.py` (loads `.env`). It **raises at import time** if a required var is missing, so importing any module needs the env populated (tests seed it in `conftest.py`). Full list in `.env.example` / README; the non-obvious ones:

- **Required:** `POLYMARKET_PRIVATE_KEY`, `FUNDER_ADDRESS`.
- `GROQ_API_KEY` — without it `analyse_market` returns `trade=False`, so the bot never trades.
- **Proxy accounts:** `POLYMARKET_API_KEY` / `_SECRET` / `_PASSPHRASE` switch to explicit-creds mode + `signature_type=3`. `/balance-allowance` returns 0 for proxies → set `OVERRIDE_BALANCE` to the real pUSD balance to unblock trading.
- **Risk knobs** (hardcoded thresholds live at the top of `main.py`): `MAX_ACTIVE_POSITIONS` (5), `SLIPPAGE_TOLERANCE` (0.05), `TAKE_PROFIT_PCT` (0 = off), `STOP_LOSS_PCT` (0.30), `USDC_APPROVAL_USD`, `MAX_GAS_PRICE_GWEI`.
- **Discord:** `DISCORD_WEBHOOK_URL` (empty = off), `PNL_REPORT_INTERVAL_HOURS` (1 — each interval sends the two-message report). The per-scan markets list is **never** sent to Discord; it stays in the console logs.
- **Scanning:** `FOOTBALL_ONLY` (**false by default — universal**: the bot evaluates *all* active markets — politics, crypto, general, plus football matches (the latter routed through the 1X2 path); set `true` only to restrict scanning to individual football matches during a tournament), `MARKET_SCAN_LIMIT` (0 = unlimited by default — pagination dynamically fetches **all** active markets, `offset += 100` until Gamma returns an empty/partial page; set >0 only as an optional safety cap on request count), `BATCH_SIZE` (12 by default — markets that pass the cheap filters are accumulated into batches of this size and sent to Groq in **one** request via `analyse_batch`, drastically cutting request count so the larger `llama-3.3-70b-versatile` model can run without hitting 429s; set `1` to fall back to per-market analysis through `process_market`), `MIN_VOLUME_USD` (10000 — lower it if today's low-volume matches get filtered out), `PROBABILITY_MIN`/`PROBABILITY_MAX` (0.45/0.95 — applied **per 1X2 outcome** (a Polymarket outcome's price *is* its YES probability); a match is analyzed only if at least one of its 1/X/2 legs lands in the window. Note: a draw's price rarely exceeds 0.45, so the floor favors 1/2 — lower `PROBABILITY_MIN` to fish for draws/underdogs), `GAMMA_ORDER`/`GAMMA_ASCENDING` (Gamma sort field, e.g. `volumeNum` or `startDate` ascending to surface imminent matches; empty by default, auto-falls-back to unordered if the API rejects it), `GAMMA_TAG_IDS` (optional CSV of numeric Gamma tag ids for a soccer/World-Cup deep-scan; off by default — needs the real tag id verified against the live API), `HISTORY_FILE` (override the `history.json` path, e.g. a Railway volume since `/app` is ephemeral + root-only), `QUEUE_FILE` (same idea for `next_in_line.json`, the wishlist queue), `ACTIVATE_QUEUE` (**false by default** — gates the entire wishlist queue on/off; when on, AI-approved markets blocked by `MAX_ACTIVE_POSITIONS` are saved and re-traded when a slot frees up).

## Architecture

`main.py` orchestrates; everything in `src/` is a focused helper. Startup: boot reconciliation → warm CLOB client → ensure on-chain approvals → loop. **Each loop iteration:** `get_account_state` → (if `ACTIVATE_QUEUE`) **prune expired wishlist entries** (`_clean_queue`, `next_in_line.json`) → maybe send the hourly P/L report → balance gate → exposure gate (at MAX positions: sleep unless `ACTIVATE_QUEUE`, which instead scans to *build* the wishlist) → (if `ACTIVATE_QUEUE` and slots free) **process the wishlist** (`_process_queue`, *before* the mass scan: re-evaluate saved markets and trade them) → fetch **all** active markets (dynamic offset pagination with a `time.sleep(0.1)` between requests, deduped by id; optional `MARKET_SCAN_LIMIT` cap) → drop those already in the persistent history → shuffle, then **stable-sort match markets to the front** (`_is_match_market`) so head-to-head/imminent games are analyzed before per-loop limits/throttle hit → `_scan_markets` (accumulate filtered markets into batches of `BATCH_SIZE` and send each batch to Groq in **one** `analyse_batch` call; throttled once per batch; `BATCH_SIZE<=1` falls back to per-market `process_market`) → `check_exit_conditions`.

**`process_market` pipeline** (constants at the top of `main.py`): classify (logged as `[Tip: Meci/Outright/General]`, by `_classify_market` from title/slug; head-to-head detection is robust — `vs`/`v`/`versus`, the binary `Will A beat B?`/`defeat` format via `extract_teams` (capitalized operands so `beat expectations` isn't a match), and `-vs-`/`-beat-` slugs — while tournament/group **outrights** (`win the World Cup`, `win Group A`, `advance`, `golden boot`) are excluded; match takes precedence over outright. Caveat: a non-sport `X beat Y` title, e.g. an election market, can still read as a match — use `GAMMA_TAG_IDS` (soccer tag) for precise filtering) → global-exposure gate → **optional football-only gate** (`FOOTBALL_ONLY`, off by default; when on, anything not `match` is dropped as `non-meci`) → volume ≥ `MIN_VOLUME_USD` → then the route branches by type (independent of the flag). All of the above is the **cheap-filter `_prepare_market` phase** (no LLM): it gathers news and returns an *analysis item* (or `None` if filtered). The Groq decision + execution happen **after**: in one batched `analyse_batch` call (the loop's `_scan_markets`, default), or via `analyse_match`/`analyse_market` for the single-market `process_market` path (`BATCH_SIZE<=1` / tests). Both feed the shared `_apply_decision` → `_execute_trade` tail. The two route-prepare branches:
  - **Match → 1X2 path** (`_prepare_match_1x2`): `parse_match_market` (`src/football.py`) splits the market's parallel `outcomes`/`outcomePrices`/`clobTokenIds` arrays into `1`=home / `X`=draw / `2`=away legs (draw detected by name, teams matched to the `A vs B` title), logged as `[Meci] A vs B | 1 (A)=.. | X (Draw)=.. | 2 (B)=..` → per-leg probability window (candidates = legs in `PROBABILITY_MIN`–`PROBABILITY_MAX`) → news → Groq returns a `1`/`X`/`2`/`NONE` pick (validated against the eligible legs, by `analyse_batch` or `analyse_match`) → the chosen leg's token/price flow through `_apply_decision` into `_execute_trade`.
  - **Non-1X2 (binary Yes/No match, or any market when `FOOTBALL_ONLY` is off) → legacy path** (`_prepare_legacy_binary`): YES-price window → per-event cap via `_extract_event_id` (skipped for `match`) → news → Groq YES/NO (by `analyse_batch` or `analyse_market`) → `_apply_decision` → `_execute_trade`.

  `_execute_trade` is the shared tail: `confidence ≥ 0.70` is gated by the caller (`_apply_decision`), then balance / duplicate-token / slippage checks → `place_limit_order` → `notify_trade`. Each filter bumps a `_scan_stats` counter; the loop logs a per-scan `[Scan] Rezultat filtrare ...` summary so you can see *why* markets are skipped → record to `history.json`. **Wishlist queue (opt-in via `ACTIVATE_QUEUE`, default off):** after the funds gate passes (balance ≥ `_MIN_BALANCE_PUSD` = 1.05) and the token/duplicate/price checks, if `MAX_ACTIVE_POSITIONS` is reached the AI-approved market is appended to `next_in_line.json` via `_enqueue_opportunity` *instead of* trading — a wishlist to act on when a slot frees up. (`process_market`'s per-market MAX check is skipped when `ACTIVATE_QUEUE` so analysis reaches `_execute_trade`; the loop's exposure gate scans-to-build instead of sleeping.) The `from_queue=True` flag (set only on the wishlist-replay path) suppresses re-queueing so a replayed item can't loop back in. Note: the old "save on lack of funds" trigger was removed — the 1.05 gate makes funds/sizing skips unreachable, so the queue is **only** for the MAX-positions case.

**Log verbosity (Railway 500 logs/s rate limit):** the per-market lines — `[Agent] Procesez piața ...` (fired for *every* market) and every per-market `[FILTER] Ignor ...` skip — are at **DEBUG**, so at the default `LOG_LEVEL=INFO` they don't emit. The aggregate `[Scan] Rezultat filtrare ...` summary, the `[Meci]` 1X2-odds line, news-found, the AI decision, `[TRADE]`, and all warnings/errors stay at INFO. The cheap-filter inner loop intentionally has **no per-market sleep** (only a 3 s throttle *after each Groq call* — i.e. once per batch, or once per analyzed market when `BATCH_SIZE<=1`), so INFO must stay quiet there or a single scan of thousands of markets bursts past the rate limit; set `LOG_LEVEL=DEBUG` to see the per-market detail again. The outer loop already cools down `_LOOP_INTERVAL` (60 s) at the end of every iteration and on every `continue`.

**Module map:**
- `config/settings.py` — `Settings` singleton + root logging config.
- `src/clob_client.py` — singleton `ClobClient` via `get_clob_client()` (never construct directly). Explicit-creds mode (proxy, sig_type 3) vs derive mode. `get_signature_type()` centralizes the signature type used elsewhere.
- `src/execution.py` — `place_limit_order` / `cancel_order` / `compute_order_size`. **The `Side` enum is defined here** (string-based), not imported from the SDK. Sizing targets **$5/order**, but `compute_order_size(price, budget=…)` caps to the budget it's given when that's under $5 (truncating so `size*price ≤ budget`), so small balances place a balance-sized order instead of being blocked. **Two guardrails (enforced in `_execute_trade`):** (1) a **3% safety buffer** — the caller sizes against `safe_balance = pusd_balance * _BALANCE_SAFETY_BUFFER (0.97)`, never the full balance, so Polymarket's dynamic fee estimate can't tip the order into "Insufficient Balance"; (2) two **local skip checks** (replacing the old rigid 5-share minimum) — the market is skipped locally (logged `[Sizing] Skip …`, *no* API call, instead of a `400 Bad Request`) if either `estimated_size < 1` (price too high to afford one whole share) or `order_total < _MIN_ORDER_VALUE_USD` (1.00, Polymarket's per-order dollar floor). Net effect: tiny balances now trade on any in-window leg where the budget buys ≥1 share *and* the order clears $1; note the $1 balance gate (`_MIN_BALANCE_PUSD`) and the 3% buffer interact, so a balance just above $1 on a cheap leg can still be skipped by the $1 order-value check. **A SELL must also pass `size=` explicitly** or it sells a price-derived quantity instead of the held amount. Supports multiple tick sizes.
- `src/reconciliation.py` — `get_account_state()` → `{pusd_balance, allowance, active_positions}`. Balance/allowance are **micro-USD (÷1e6)**; positions come from the Data API enriched with P/L fields, `outcome`, and `event_id` (from `eventSlug`). `compute_portfolio_summary()` builds the Discord report.
- `src/position_manager.py` — `check_exit_conditions()`: opt-in take-profit/stop-loss → SELL at best bid; has its own 30-min per-token exit cooldown.
- `src/allowance.py` — one-time on-chain approvals (pUSD + CTF) targeting the **V2** exchanges; EOA sends tx directly, proxy routes through `Safe.execTransaction`.
- `src/football.py` — `parse_match_market(market)` maps a Gamma match into 1X2 legs (`1`/`X`/`2` with team names, prices, token ids); `extract_teams`, `format_legs`. Pure Python (no new deps → nothing to mock in `conftest`). Returns `None` for binary Yes/No or unparseable markets so the caller can fall back to the legacy path. **Assumes the 1X2 is a single market with parallel `outcomes`/`outcomePrices`/`clobTokenIds` arrays** — if Polymarket ever splits a game into separate per-outcome binary markets, those degrade to the legacy YES/NO path (still tradeable, just not grouped/logged as one 1X2).
- `src/ai_analyser.py` — Groq via the OpenAI-compatible SDK (model in `_MODEL`, currently `llama-3.3-70b-versatile`) → strict JSON decision. `analyse_market` (binary YES/NO) and `analyse_match` (1X2 — picks `1`/`X`/`2`/`NONE`, validated against the eligible legs so it can't pick an out-of-window outcome) are the single-market calls; **`analyse_batch`** packs many markets (both kinds) into **one** request and returns `{market_id: decision}` (each validated per-kind; ids missing from the array default to `trade=False`; rate-limit/API errors re-raise so the caller doesn't record them, parse/no-key errors return all-false). Prompt-injection hardened (untrusted title/news wrapped + sanitized); tenacity retries 4×.
- `src/news_monitor.py` — `fetch_free_news` (Google News RSS, no key, used by the loop) vs `fetch_latest_breaking_news` (NewsAPI + X).
- `src/notifications.py` — Discord webhooks, three message types: `notify_trade` (BUY/SELL, with outcome), `notify_portfolio` (financial status only — "💵 Status Financiar": totals + P/L), `notify_positions` (open-positions inventory — "📦 Poziții Active", one numbered line per position; empty → "Niciuna."). All **no-op without a webhook and never raise**, safe to call inline. `_maybe_send_pnl_report` (in `main.py`) sends **both** messages — portfolio **then** positions — once per `PNL_REPORT_INTERVAL_HOURS`, never per loop. There is **no** per-scan markets webhook (removed by design — the scanned-markets list lives only in the console logs).

## Cross-cutting concepts

- **Account-mode duality is the central complexity.** EOA (`key == funder`) vs proxy (key signs for a Safe/Magic wallet that holds the funds). It changes auth (`clob_client.py`), approval execution (`allowance.py` Safe path), and balance reporting (the `OVERRIDE_BALANCE` workaround). Touch any of those with both paths in mind.
- **`py-clob-client-v2` is required, not a typo.** Polymarket migrated to V2 orders / pUSD collateral; the official `py-clob-client` is rejected by the server with `invalid order version`. Don't "upgrade" to it.
- **Persistent analysis history (`history.json`):** loaded first in `main()`, it filters markets analyzed within `_CACHE_TTL_SECONDS` (4h cooldown) out of the fetched batch *before* processing, so Groq isn't re-called for them across restarts. Recorded via `_record_analyzed` after each LLM call; expired entries pruned on load; the file is gitignored.
- **Wishlist queue (`next_in_line.json`, opt-in via `ACTIVATE_QUEUE`):** off by default — every queue function (`_clean_queue`/`_process_queue`/`_enqueue_opportunity`) is gated behind the flag, so the file is never touched unless enabled. When on, AI-approved markets that hit `MAX_ACTIVE_POSITIONS` (see "Wishlist queue" above) are saved here and re-evaluated **first**, each loop a slot is free, before the mass scan — so the wallet acts on the best saved ideas without re-scanning ~2100 markets. Each entry stores `market_id`/`token_id`/`market_title`/`predicted_outcome`/`original_price`/`confidence`/`added_at` (+ `event_id`/`tick_size`); deduped by `market_id`, capped at `_QUEUE_MAX_SIZE` (10, highest-confidence kept), pruned past `_QUEUE_TTL_HOURS` (12h, so stale news isn't re-traded). Re-evaluation (`_reevaluate_queued`) pulls a **fresh** orderbook price, re-runs Groq, and trades only on a renewed YES; each item is removed after analysis regardless of outcome, and `_process_queue` stops (leaving the rest) once balance drops below `_MIN_BALANCE_PUSD` or `MAX_ACTIVE_POSITIONS` is hit. Robust to a missing/corrupt file (treated as empty); gitignored.

## Testing

- **No `__init__.py` anywhere** — the project runs from the repo root so `config`, `src`, and `main` import as top-level modules. Keep new code root-relative.
- `tests/conftest.py` **mocks every heavy/native dependency** (`py_clob_client_v2`, `openai`, `web3`/`eth_account`, `tenacity`, `defusedxml`, `httpx`) and seeds required env vars before any project import — the suite needs only pytest installed. Adding a module that imports a new third-party package means mocking it there, or collection breaks.
- `test_bot.py` imports the **real** helpers from `main` / `src` (not local copies), so changing those functions is covered directly by the suite.

## Gotchas

- Units differ by layer: CLOB balance/allowance are micro-USD (÷1e6); market and order prices are plain 0–1 probabilities.
- Event clustering correlates Gamma markets to open positions via the **event slug** — `_extract_event_id` (markets) and `reconciliation` (positions) must both keep reading `eventSlug`, or the per-event cap silently stops limiting anything.
- The git tree contains a junk file whose *name* is a full Windows path (`C:...tests__init__.py`, with an escaped colon). It is not a real package file — ignore it.
